OT Builder is becoming a module

It now sits inside a container app alongside DOT.log. Its own code was not rewritten, reorganised, or optimised. Here is exactly what moved and what did not.

The short version

The container gives each app its own page rather than merging them into one. OT Builder keeps its own document, its own stylesheet, its own bottom navigation and its own web address. Nothing from DOT.log can reach it.

This was chosen over embedding because DOT.log styles the whole page rather than scoping to a root element, and because both apps place a fixed navigation bar at the bottom of the screen. Sharing one document would have meant reworking OT Builder's styling to survive it. Separate pages avoid that entirely.

Unchanged Verified by checksum

app.js, styles.css and templates/Blank OT form.pdf in the container are byte-for-byte identical to the files at the source tag. The OT calculations, PDF generation, signature handling and project storage were not touched.

Shipping an OT Builder update from now on

Update ownership stays split: DOT.log is maintained by Bruce, OT Builder by you. The container is arranged so the two of you never edit the same file and never need to coordinate a release.

  1. Build and tag your release exactly as you do today.

    Nothing about how you develop OT Builder changes.

  2. Replace the contents of the container's /ot/ folder.

    Keep the two added lines in index.html, or re-add them.

  3. Bump the version and file list in /ot/version.json.

    This is the only file that tells the container an update exists. It lives in your folder, so shipping never touches anything shared.

Users then see OT Builder — update ready on the container's front page, with its own button. Pressing it refreshes your app only. DOT.log's stored copy is not touched, and vice versa.

Not built yet. Stage 1 delivered the container and both apps in their own pages. Offline support, the shared appearance switch and the update system described above are stages 3 to 5. The version.json contract is fixed, so you can add the file now.

One thing needed from you

The version number disagrees with itself

The folder is tagged v1.4-integration-ready, but APP_VERSION in app.js still reads v1.3.0, and that is what the debug panel reports.

The update system reads the version to decide what to show users, so this should agree before stage 5. It was left alone deliberately — changing it means editing app.js, which was out of scope here.

Facts worth carrying forward

Nothing about storage changed

otFormBuilder.theme, otFormBuilder.draft and the ot-form-builder-files database are untouched and uncontested. DOT.log uses entirely different keys and a different database, so there is no shared state between the two apps and nothing to migrate.

Do not name a container cache ot-form-builder-*

Your disableServiceWorkerCaching() deletes every cache key with that prefix on load. A container cache using that name would erase its own offline copy on every visit. The container's caches are named cna-ot-* to stay clear of it — worth remembering if the cleanup prefix ever widens.

The debug mode survives intact

Because OT Builder keeps its own address, ?otDebug=1 works exactly as documented. That is the first thing to reach for if a user reports a problem after the move.

The top bar is the container's, not yours

It is a fixed bar rather than a floating chip because a chip sat on top of the OT Form Builder title. The bar reserves its own strip via a :has() rule on body, so nothing in your layout is covered, and your fixed bottom navigation is unaffected.
